# 02｜系統分析 SA

## 文件目的與使用方式

本文件定義跨模組的業務結果、角色、規則及例外。各模組完整 use case、欄位、API 與驗收見 `docs/modules/`；狀態轉移見 `05-workflows.md`；程式介面以 OpenAPI/Event schema 為準。本文不以一句「支援KYC/CRM」代替可實作規格。

## 1. 使用角色與作業分工

| 角色 | 日常任務 | 必要判斷 | 系統替代的庶務 |
|---|---|---|---|
| 官網申請人／客戶 | 簽署、補件、訂閱、查通知、客服 | 本人資料、同意與選擇 | 預填非敏感資料、續填、進度、回執與通知 |
| 契約作業 | 例外申請、核對資料、公司承諾流程 | 被授權的承諾或拒絕 | 收件、完整性、提醒、契約產出與寄送 |
| KYC/適合度審查 | 資料核實、屬性與服務適配 | 審查結果與條件 | OCR草稿、交叉檢查、問卷計算、摘要 |
| AML承辦／主管 | 篩檢、可能命中、EDD、監測 | 結案、限制、申報流程 | 名單查詢、比對候選、週期更新、證據包 |
| 分析師／研究覆核 | 審閱候選、修訂、覆核、簽章 | 研究與建議的專業責任 | 接案、證據整理、差異比對、簽章後交付 |
| 法遵 | 制度、廣告、報告指定檢視、例外 | 政策核准與法遵結論 | 抽檢名單、留存、修正追蹤 |
| 行銷 | 來源與漏斗、受眾與轉換分析 | 活動配置、核准素材使用 | 歸因、分群、報表、待辦清單 |
| 業務／主管 | 續訂、升級、流失挽回、交接 | 維護行動、轉換證據、爭議裁定 | 優先排序、聯絡摘要、提醒、歸屬與試算 |
| 客服 | 線上線下案件、客訴與轉介 | 回覆、升級及結案 | 同案彙整、分類、草稿、SLA追蹤 |
| 財會／覆核 | 收款對帳、履約、收入、退款、結算 | 金額政策、差異核決、支付釋出 | 匯入配對、分錄草稿、試算、關帳檢查 |
| 稽核 | 抽樣、證據匯出、缺失改善 | 獨立查核與結案 | 證據鏈、版本校驗、報表與追蹤 |
| 系統維運 | 可用性、排程、權限技術實施、恢復 | 維運操作 | 告警、重試、健康檢查、備份驗證 |

職稱不自動給所有權限；role、有效任職/登錄狀態、tenant、案件範圍、資料敏感度與動作共同決定。

## 2. 客戶與契約的端到端流程

### SA-F01｜自助申請與先簽文件

入口接受 LegendFlow 已驗證 session，建立單一 customer 與獨立 application。未驗證 email/電話只能成為待確認聯絡點，不能自動合併他人的身分。第一筆來源、後續觸點及行銷同意分別留存。客戶選擇服務條件、查看契約版本與聲明，完成本人簽署；記錄文件包版本、內容hash、證據引用、時間、簽署方法及交付回執。

簽後進入 KYC/適合度/AML 資料收集，允許跨裝置續填。每一項文件可在線上完成，但客戶勾選AML聲明與公司內部AML核決為不同事實。若逾時或補件，保留已簽版本，不把簽署時間改成後續審查時間。

### SA-F02｜審查、公司承諾與權限

自動檢查必填、格式、附件安全、文件有效性與答案矛盾；有風險或缺漏轉有責任人的案件。審查器各自輸出 KYC、適合度與 AML gate 結論與有效期限，專業決策附理由及人員。公司承諾命令在同一交易鎖定待承諾申請與 gate 快照，核對決策仍有效、版本未換、無限制，再依授權者同意契約。

契約生效依正式條款記錄 `effective_at`；權限由服務範圍、有效契約、應繳條件、審查有效性、限制旗標及有效期間共同計算。只付錢或只有客戶簽署不能開權限。允許同一客戶多份有效契約，撤銷單一契約不撤掉其他合法服務。

### SA-F03｜付款、拒絕與終止

如允許審查前付款，顯示待審查/待承諾，款項列待處理或預收，不能視為已履約服務收入。被拒絕、撤回或不成立時，建立退款案件與財會核決流程，保留原付款、退款及通知時間；支付逾時先查外部狀態，避免重複退款。

客戶可依契約提出終止/退款。系統保存收受契約與終止申請時間，套用核准的退費公式版本；不要把投顧管理規則的收受契約後七日終止權寫成一律簽約前等待七天。條款正文與公司承諾法律效果由正式文件核定，見 `17-sources-compliance.md`。

## 3. 研究到即時服務

### SA-F04｜候選接收與研究協作

候選可由 Persona 自主流程或分析師發起。保存 source_system、persona/pool、run/artifact/evidence refs、來源版本、內容hash、事件發生/資料可得/本平台收件時間。驗 schema、tenant、來源信任、授權和完整性後進覆核佇列；不直接推給客戶。下載外部檔案要有allowlist、大小與型態限制和掃毒，不能任意追隨模型給的URL。

分析師可以直接審閱，或針對候選版本向Servant要求補資料/重分析/改報告/改訊息草稿。修訂非同步回來後形成新版本；舊版本覆核不能套到新版本。並行修訂衝突需人工選擇或再合併，不採最後寫入覆蓋。來源研究失敗與空報告是不同狀態。

### SA-F05｜覆核與簽章包

正式報告包含主題/標的、分析日期、來源與時點、方法/假設、結論與風險、適用服務、撰寫/覆核/核准引用。建立 recommendation series 連結首次、更新與結束建議；一份有效研究可被多則合乎其範圍的訊息引用，但新增標的、方向、進出依據或重要風險變動須新簽研究/補充報告。

簽章前完成必要專業與法遵審查；freeze report、recommendations、已核准各通路文字、audience policy、有效期限及引用。分析師看到整包內容與差異，重新驗證身分並簽署確切 digest。保存簽章provider、方法、身分證據、驗證結果、內容hash與signed_file_hash；圖章圖片不等於已驗證電子簽章。

### SA-F06｜簽後自動發布、交付與訂正

有效簽章核驗交易寫入 durable publication request，系統立即排入發布，不需再點第二顆發布按鈕。若資料過期、權限異常或全域緊急暫停，狀態清楚顯示blocked與原因；不向客戶提供未核准內容。不要簽後再由LLM生成新的投資文字。

發布保存收件快照；每次送出仍重查即時權限、撤回/到期、通路binding與偏好。LegendFlow提供可授權查閱的研究連結，SMS/即時訊息有簡短內容與同一report/recommendation reference。accepted、sent、delivered、read各自有供應商證據；無已讀回執就unknown。

訊息逾時後不能無條件重送進出場指示，先確認provider既有結果並重新評估有效性。訂正、撤回或新方向保留原記錄、發新版本與更正通知，串回原audience和新的合法收件資格；不覆寫歷史訊息，不把Persona下單時間填為研究發布時間。

## 4. CRM 與公司 Pool

### SA-F07｜漏斗及可執行名單

依來源→有效接觸→申請→客戶簽署→資料完備→審查→公司承諾→付款/生效→服務開通→續訂/升級/流失建立可量測狀態；付款可提前發生，所以不能用單一線性stage遮掉真正 gate。漏斗看的是分期 cohort 轉換，不能把活動次數當客戶數。

工作清單每列必含客戶、契約/機會、觸發理由、資料時點、負責人、下一步、到期日、允許聯絡渠道、抑制原因、預期服務與處理結果。AI可排序與草擬；客戶需求、服務適合度、未解決問題與過往行動是依據，報告未閱讀不能單獨判為流失。升級前需對應服務的適合度再評估。

### SA-F08｜歸屬與真實轉換

原行銷來源、現維護人、機會負責人、客服owner、實際促成者分開。網站自行續訂，不因名下有人就給其獎金。業務有具體介入且促成續訂/升級，保存行動、客戶回應、時間與轉換關聯，才成為候選計獎證據；AI建議、群發與空白通話記錄不構成轉換。

離職事件即終止維護資格並轉公司Pool；舊交易歸屬保留。客戶服務中斷一週的實作解讀依決策 BIZ-POOL-01，暫以全部付費服務中斷連續七天作測試基線，未定案不啟用正式自動移轉。公司Pool重新開發者成功轉換後取得該筆業務歸屬；單純認領不能領獎金。合約/客服持續性與業務歸屬獨立，不能讓客戶因業務離職失去服務。

## 5. 獎金與財會

### SA-F09｜可重算的獎金

M12僅消費M14確認的未稅服務收入及可歸屬退款調整，不讀信用卡入款直接發獎金。每筆保存來源收入、contract/service lineage、行銷cohort、合格業務證據、規則版本、rate、係數、分配、收受者與理由。未核准總獎金率回傳policy_not_approved而非默認3%。

按月形成試算→差異處理→覆核→核准→匯出→發放確認；關帳後用調整，不改舊帳。退款沖回原計獎版本與原收受人，不把前員工獎金扣在接手業務身上；是否可實際扣薪/追償為另行人事核准流程。

### SA-F10｜收入、退款與內控

契約履約排程、bill、payment、PSP settlement、銀行入帳、invoice/receipt、revenue recognition、refund與GL輸出分開保存。付款當下的gross、tax、fee與net不混淆；支付手續費不是任意扣減服務收入。跨日/跨月和部分退款對應相同service period。每個對帳差異有owner、理由與resolution證據。

財會maker不可核准自己的退款、關帳或獎金撥付。對帳差異、重複invoice、孤兒payment、重複refund、收入排程超額、分錄不平、佣金超過池額都要拒絕或進例外。稽核可由交易一路追到契約/服務/交付與人員權限快照。

## 6. 線上線下客服

網站、LINE/即時訊息、email、電話及現場共用case與interaction。未確認身份時以暫存contact管理，不把電話文字強行合併正式客戶。保留原始內容引用、客戶、渠道、分類、優先度、SLA clock、owner、相關契約/研究/付款、下一步與resolution。

AI分類、摘要和草稿帶來源及可編輯狀態。投資問題送合格分析師；客訴、資安、退款、身分盜用與受限制事項採對應流程。客服只能看到「需專責處理」等最小旗標，不看到AML可疑申報詳情。電話/現場處理需補登時間與證據；未留錄音不能偽造錄音存在。結案後再來信可reopen同案並保留原SLA與新增週期。
